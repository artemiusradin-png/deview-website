# EVDEV and Deview SEO comparison
Audit date: 23 October 2026. Production domains: https://evdev.dev and https://deviewai.com.

## Assessment
EVDEV has the stronger visible content strategy: a tightly defined Shopify audience, buying-stage guides, original research and a larger body of independently published reviews. This does not establish that it receives more organic traffic or ranks above Deview. Search Console, keyword-volume data, backlink data and comparable field-performance data were unavailable.

Deview already has a substantial SEO foundation. The next investment should concentrate on selected existing pages, relevant proof and contextual links. A broad new batch of service pages is not the immediate need.

## What was checked
- Fetched both homepages, robots.txt and XML sitemaps directly.
- Crawled all 145 Deview sitemap URLs and 13 selected EVDEV interior URLs; inspected server-returned metadata, headings, structured data and links.
- Checked HTTP/HTTPS and www variants, a nonexistent Deview route, and the client portal.
- Reviewed public Clutch, GoodFirms and Shopify partner profiles and Google's current documentation.
- Search results sometimes returned older versions of Deview pages. Direct production HTML takes precedence in this report.
- The local checkout is behind origin/main and contains existing user changes. Production findings are not inferred from that checkout.
- PageSpeed Insights returned HTTP 429 for both domains. No performance score, Core Web Vitals comparison or ranking claim is made.
- Evidence: /tmp/deview-seo-audit-2026-10-23/initial.json, crawl.json, crawl.py and saved HTML snapshots. The crawl checks HTML, not a full browser-rendered or accessibility audit.

## Prioritized improvements

### 1. Repair the www domain behavior
HTTPS requests to www.deviewai.com timed out in both requests and curl; the web fetcher also could not open it. DNS resolved www to 192.64.119.14 and the apex to 216.198.79.1. An HTTP request to www returned a 302 pointing back to the same HTTP URL.

Inspect the DNS/domain-forwarding configuration and Vercel domain assignment. Ensure both HTTP and HTTPS www requests reach a valid TLS endpoint and permanently redirect to the canonical production host. Verify after any change from more than one network. The apex domain itself worked.

### 2. Reconcile the GoodFirms rating
The live homepage advertises a five-star GoodFirms rating. The linked public profile fetched through the web tool says no reviews have been submitted. A direct requests fetch was blocked with 403, so it did not provide additional confirmation.

Verify the correct profile and any pending review. Until the public rating exists, use an accurate directory-listing label or remove the rating claim. This is a credibility issue, not evidence of an algorithmic penalty.

Also align public directory service descriptions and pricing where appropriate. Clutch still shows three service lines and empty focus/industry/client sections, whereas the website now presents five practices.

### 3. Strengthen direct links and proof
- Homepage AgroPlatforma and Unified Portal cards currently link to /en/case-studies. Point them to /en/case-studies/agroplatforma and /en/case-studies/covenant-desk.
- The AI-development page uses older case-index fragment links. Prefer the corresponding individual case URLs.
- Link the document-automation article to the relevant document-processing solution and a matching delivered case; reciprocate from the solution page where useful.
- The bank document-processing solution currently cites the senior-care documentation case. Keep that evidence accurately scoped, and add directly relevant lending evidence where the implementation supports it.
- Expand priority case studies with the initial workflow, inputs, integration boundaries, measurement period, outcomes, limitations and a named client quote when authorized. Word count itself is not the objective.

### 4. Concentrate the content investment
The Deview sitemap has 145 distinct URLs, including 95 beneath /en/solutions/ plus the solutions index. The presence of many pages is neither a ranking advantage nor proof of poor quality. Sampled solution pages already contain substantial modules, architecture, controls and FAQs.

Choose a small initial set based on commercial fit, demonstrated delivery and Search Console opportunity:
- Hong Kong custom software and AI implementation.
- Lending systems and borrower workflows.
- AI document processing for financial operations.

Oil-and-gas project controls is a credible second candidate based on existing case material. Prioritize it sooner if sales opportunity or search data supports that choice.

For each selected intent, improve an existing destination before creating another page. Check whether the homepage, custom-development page and Hong Kong market page attract the same queries before merging or retargeting anything.

### 5. Publish useful buyer content and keep it accurate
Start with a few pieces such as:
- How much does a custom loan management system cost? Explain cost drivers and scope assumptions using supported project experience.
- AI document processing versus OCR for lending workflows.
- How to evaluate document-extraction accuracy: field accuracy, exceptions, human review and cost per completed file.
- Private LLM deployment costs: hosting, retrieval, evaluation and operational support.

Use named technical authors, real examples, sources and meaningful update dates. The Insights index promises a monthly article, but its three visible articles are dated March–April 2025; update that promise or establish a sustainable publishing schedule. Do not change dates without substantive updates.

### 6. Complete secondary metadata
Add Open Graph/Twitter defaults with page-specific overrides. Add Article/BlogPosting data with visible authors and accurate dates, and breadcrumbs where appropriate. Deview's service and solution pages already contain Service, WebPage, BreadcrumbList and FAQPage markup; do not rebuild that work.

Google ignores meta-keywords. Keyword research belongs in the page strategy, titles, headings, useful copy and internal links. [Google documentation](https://developers.google.com/search/docs/crawling-indexing/special-tags)

Google says there is no special schema or extra technical requirement for its AI search features. Do not prioritize llms.txt or more schema ahead of useful content and evidence. [Google AI search guidance](https://developers.google.com/search/docs/appearance/ai-features)

## Keyword plan
The accompanying CSV contains proposed query groups and destinations. These are hypotheses based on existing services and proof, not measured search volumes, difficulty scores or confirmed rankings. P1/P2 indicate editorial priority, not predicted search performance.

Use one preferred page for each distinct search intent, with related wording on the same page. Validate:
1. Search Console query/page/country data over the last 3–6 months, including indexing status.
2. Local search results and commercial versus informational intent.
3. Country-specific keyword volume and competition using an appropriate keyword data provider.
4. Fit with real project experience and sales economics.
5. Whether an existing page already serves the query.

Do not publish separate near-identical pages for every synonym or city. Hong Kong is the starting assumption because the current homepage title and named lending clients support it. Confirm sales priorities before expanding locations or translating content.

## Practical sequence
- First: repair www behavior, reconcile the rating, improve direct case links, establish Search Console and inquiry-conversion baselines.
- Next: choose 6–8 priority existing landing pages and strengthen their buyer fit, evidence and contextual links.
- Then: publish 2–3 substantive buyer guides and expand the strongest case studies; seek legitimate client reviews and client/partner mentions.
- Review after enough crawl and impression data accumulates: non-brand impressions/clicks by cluster and country, qualified inquiries, and pipeline sourced from organic search. Treat 30/60/90-day checkpoints as review dates, not ranking promises.

No website source, deployment, DNS, directory profile or external message was changed during this audit.
